# GTNH 2.8.1 next to 2.9 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve a GTNH 2.8.1 dataset next to 2.9. Make every plan belong to one game version. Convert plans between versions into a new plan. Compute machines and power the 2.8.1 way on 2.8.1 plans. Switch the in-game mod and the community library off in this deployment.

**Architecture:**
- **Oracle.** The oracle mod gets a build-time GT5U selector and one version-specific source file for the ore export. The same pipeline normalizes a 2.8.1 export.
- **Plans.** A plan carries `gameVersion`, a version family such as `"2.9"` or `"2.8.1"` (never a dataset id).
- **Datasets.** The client keeps one loaded dataset per family, and the active tab picks it. Every recipe refresh, recipe add, icon refresh and paste checks that the loaded dataset's family equals the plan's.
- **Machine code.** Machine and power code take the game version as a required argument, so the compiler finds every call site.
- **Off switch.** One deployment setting switches the mod and the community library off at their entry points and routes.

**Tech Stack:** Next.js App Router, TypeScript strict, Zustand, Zod, Vitest, React Flow; Java 8 Forge mod on Gradle (GTNH conventions); Node `.mjs` pipeline scripts; Playwright (`playwright-core`) for real-app checks.

**Spec:** `docs/superpowers/specs/2026-10-22-gtnh-2-8-1-support-design.md`. Read it first: this plan argues from it.

## Global Constraints

- **Versions served.** Only GTNH 2.8.1 and 2.9. 2.8.4 stays retired: `HIDDEN_DATASET_VERSION_IDS` keeps `local-2.8.4`.
- **The default.** 2.9 stays `latestStableVersion`, the default for new players.
- **2.9 players.** They notice nothing but the new choice. Their plans, numbers, ids and speed stay the same.
- **Arriving and converted plans.** Every one opens as a NEW design via `importProjectAsDesign`. No app path calls `setProject`. The original plan is never modified.
- **No silent cross-version numbers.** A 2.8.1 plan never silently shows 2.9 numbers or keeps a recipe body from another version. That covers paste, blueprints and pockets too. Wrong without a warning is the failure.
- **Old plans.** Plans saved before this have no version field and read as 2.9. A load never writes (`src/store/CLAUDE.md`, "One mode").
- **Persisted settings.** A setting with no visible control is never persisted. The remembered new-plan version has a visible control, so it may be.
- **No re-solves.** Display dials never re-solve. A dataset switch never re-solves a plan against the other version's recipes.
- **Copy.** Player-facing copy is plain and short, with no em dashes and no quips. A test that pins copy changes in the same commit as the copy.
- **The off switch.** The mod and the community library are switched off behind ONE deployment setting, at entry points and routes, with no code deletion. The default is off: unset, or any value but `on`, means switched off (Decision 2). Tests pin both sides of the setting.
- **Data.** Prefer exported NEI/runtime data over new hand tables (AGENTS.md invariant).
- **Board performance.** No DOM measurement per edge or per frame, nothing O(nodes x edges) per frame, and hover never rebuilds the board. Board performance changes need a before/after profile.
- **Comments** state the rule and why. No dates, names or "used to" stories.
- **Generated files** never go in the repo root. Probes, captures and logs go in `scratch/`.

   - Case: an old IndexedDB record, a plan file, a `#p=` link, an account-synced plan or a live room.

4. **A synthesized recipe on a 2.8.1 plan.**
   - Case: a power card, the Auto Workbench, a steam singleblock or the crop placeholder.
   - Expected: it is computed with 2.8.1 rules like a dataset recipe. It never falls back to 2.9 because it carries no `source.datasetVersionId`.

5. **A plan whose version this deployment does not serve.**
   - Case: a plan file stamped `"2.8.4"` or `"2.10"`, or a remembered new-plan choice no longer in the manifest.
   - Expected: Decision 1. New plans fall back to 2.9.
